# Render Free + TiDB Cloud Starter

1. Create a TiDB **Starter Free** instance. Select Connect → Python to find host,
   port and username. Set the database password in TiDB; do not commit it.
2. In Render choose New → Blueprint, select this GitHub repository and `main`.
   It reads `render.yaml`, which explicitly selects `plan: free`.
3. Enter DB_HOST, DB_USER and DB_PASSWORD in Render's environment form. DB_PORT
   defaults to 4000; check it against TiDB Connect. DB_NAME defaults to TiDB's
   existing `test` database; change it if using another database you created.
4. Confirm the service is Free with no paid add-ons before deploying. SECRET_KEY
   is generated by Render; PUBLIC_URL defaults to RENDER_EXTERNAL_URL.
5. First start creates empty application tables in the selected database.
   After successful deployment, set INIT_DB=0 in Render. Schema upgrades are
   separate; this initializer does not migrate an existing legacy schema.
6. Open the generated HTTPS onrender.com URL, register a new account and store
   its recovery code. Local accounts and financial records are NOT uploaded.

TiDB connection uses verified TLS with Render's system CA bundle. Never disable
certificate or hostname verification to solve a connection error.
If TiDB restricts network access, allow the outbound IP ranges shown by your
Render service; do not weaken the allowlist to all addresses as a shortcut.

Render manages public TLS. Do not run Caddy or `serve.py` on Render.
`serve_render.py` binds PORT and trusts the final managed ingress proxy. This
entrypoint is only for Render, not for a VPS directly exposed to the internet.
Do not expose it to untrusted peers via a private service or add a CDN without
reviewing proxy trust. Smoke-test actual client IP handling after deployment.

Free services sleep when idle. Starter database usage must stay within its free
quota; do not enable paid scaling to continue this free setup. Data backup and
restore remain necessary. Test login, rate limits, cross-account isolation and
CRUD on the actual TiDB cluster before inviting users.
